# Working cue-learning demo

Open **http://127.0.0.1:8767** while the local server is running. The page replays actual recorded choices, shows trained/untrained/shuffled-label results, and can launch a new full experiment with a chosen seed. Runs remain local and are never overwritten.

To start the server again:

```bash
cd /path/to/flybrain
.venv/bin/python -m brainlab.demo_server --port 8767
```

Or run without the interface:

```bash
.venv/bin/python -m brainlab.learning --seed 42
```

## What learns

A separate, reward-trained linear action readout learns to choose left or right from the activity of the full 166,700-neuron MaleCNS network. All 25,582,938 connectome weights stay fixed. This is a first engineering milestone, **not learning inside the biological circuit**.

Blue/orange are symbolic labels for left/right R1–R6 stimulation. We vary current from 18 to 24 model units and randomly omit 10% of receptors each trial. Lamina current is held at 12. Each trial starts with a fresh brain and runs for 100 ms. Downstream features exclude all directly stimulated retinal and lamina classes, subtract a tonic-only calibration response, and normalize the resulting vector. The readout receives no cue label, target, or game state.

The external readout has 156,209 weights initialized to zero. Training samples a Bernoulli action and applies a policy-gradient update with reward +1 for correct, −1 for incorrect. Evaluation uses greedy choices with frozen weights on new stimulation draws. Task labels only calculate reward and scoring. This simple binary task is deliberately easy; no navigation or delayed memory is claimed.

## Measurement protocol

- 64 balanced training trials and 32 balanced evaluation trials, with seeded randomized order.
- Predefined passing criterion: evaluation accuracy ≥80% and ≥20 percentage points above the untrained readout.
- Frozen untrained readout: constant tie-broken action, 50% on balanced labels.
- Zero-feature control: removes neural information, also 50% on balanced labels.
- 1,000 evaluation-label permutations test association; this is a shuffled-label null distribution, not an independently trained shuffled-cue policy.
- Training readout checkpoint, eligible-neuron mapping, baseline counts, evaluation features, input/state/spike artifacts, and all choices/rewards stored under each run directory.
- Evaluation asserts exact frozen weights throughout. Simulation graphs are loaded fresh for each trial and never passed to the readout update.

These controls do **not** establish that connectome wiring is necessary. A direct-input classifier could likely solve this engineered task too. A wiring-shuffle ablation, multiple-task evaluation, and internal synaptic plasticity would be separate work.

## Initial result

Seed 42 (`20260914T211325-cf1f193e2b41`) achieved **32/32 evaluation choices correct**, versus 50% untrained and 49.75% mean shuffled-label accuracy. Training success was 87.5% in the first 16 trials and 100% in the last 16. A small held-out set and highly structured cues limit generalization claims.

Seed 43 (`20260914T211638-b9bbfd482fe6`), launched through the local HTTP interface, independently completed 64 training and 32 evaluation trials: **32/32 correct**, 50% untrained, 49.96% mean shuffled labels. First/last 16 training success was 93.75% / 100%. Both seeds passed the predefined immediate-choice criterion. The full automated suite passes **24 tests**, and the UI event checks pass.

The replay's T-shaped diagram illustrates a recorded decision. Its marker position is not generated by simulated legs or locomotion. The demo intentionally labels this as replay, not a live fly moving through a maze.

## Verification

```bash
.venv/bin/python -m pytest -q
node scripts/check_learning_ui.cjs
```

Tests cover reward-update direction, learning from reward without a target argument, frozen readout evaluation, exclusion of directly stimulated cells, UI replay/selection/launch event wiring, existing simulator numerical checks, and run recording. The local HTTP launcher was exercised with a real second run, plus rejection of invalid seeds, cross-origin launches, and concurrent launches.
